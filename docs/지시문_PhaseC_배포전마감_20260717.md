## 검증 결과 (2026-07-17, 클로드 코드)

### §1 조사 이중 표기
`term-guard.ts`의 `hasBatchim`을 export하고 `section9.ts`에 `withGwaJosa()` 헬퍼 신설 —
`build-couple-template-context.ts`·`section9.ts` 두 곳의 `${i.withPosition}와(과) ${i.type}`를
전부 교체. 전체 코드(`src/`) 전수 검색 결과 고객 화면에 노출되는 "X(Y)" 패턴은 이 2건뿐이었고,
나머지 2건(`term-guard.ts:399,410`)은 게이트 위반 로그 메시지로 `console.warn`+DB 저장 전용,
고객 화면에 렌더되지 않아 수정 대상 아님. 두 커플 PDF 재렌더로 "시주와 지지형", "월주와
천간충", "년주와 원진" 등 정상 출력 확인.

### §2 판형 재설계
이전 사이클에서 완료된 상태 — 섹션 밴드(큰 숫자)·본문+사이드바·풀쿼트·하단 결론 배너 +
명식표 천간/지지 세로 분리(사장님 7/17 통과) 그대로 유지. 이번 턴엔 §1 조사 수정만 반영해
재렌더, 오버플로우 0건·20페이지 유지 재확인.

### §3-1 홈 섹션 이동
`src/config/product-sections.ts` — `couple-match`를 "두리의 연애 풀이" 배열에서 제거하고
"LUNA LIFE RESEARCH — 인생 리포트" 배열에 추가. 홈(`ProductLineup`)·상품 목록(`/products`)
둘 다 이 설정을 공유해 한 곳 수정으로 양쪽 반영 확인.

### §3-2 카드 문구 — 0f047e4 충돌 보고 후 처리
커밋 `0f047e4`(7/14)가 "카드 단계 페이지 수 노출 금지"(상세 페이지에서만 노출) 원칙으로
`life-analyst-report` 카드에서 "A4 20페이지"를 이미 제거한 상태 — 지시문의 카드 문구
"A4 20페이지 PDF · 두 사람 교차 백테스트"는 이 원칙과 충돌해 구현 전 사장님께 보고,
**"0f047e4 원칙 유지"**로 확정. `products.seed.ts` value_line을
`"정식 합병 실사 보고서 PDF · 두 사람 교차 백테스트"`(페이지 수 제외, life-analyst-report와
동일 패턴)로 반영. 페이지 수(A4 20페이지)는 상세 페이지 WHAT'S INSIDE 섹션에서만 노출.

### §3-3 상세 페이지
`products/[slug]/page.tsx`에 couple-match 전용 "WHAT'S INSIDE" 섹션 신규 — 구성 요소
5종(명식표 2단·합충 관계도·2인 세운 곡선·커플 백테스트·케미스트리 리포트) 리스트 +
"A4 20페이지 — 한 페이지에 하나씩, 서로 다른 근거로 채워집니다" 프레이밍(0f047e4가 예고한
"1페이지=1개 의사결정" 톤) + 생성 소요 안내는 실측값 없이 "결제 후 자동 생성되며, 생성
진행 상황은 화면에서 실시간으로 안내해드려요"로 자리만 확보(허위 수치 없음). `description`도
채팅형 톤에서 "합병 실사 보고서"·리서치 톤으로 재작성.

### §3-4 두리 등장 금지 전구간 점검
홈 카드·상품 목록 카드·상세 페이지(스크린샷 확인) + 체크아웃 라우팅·진행 페이지·완료
페이지·PDF 고정 섹션(코드 확인, 전부 "두리 금지" 주석으로 이미 방어돼 있음) — 전 구간에서
couple-match 관련 두리 노출 없음. 유일한 위반이었던 홈 섹션 타이틀 "두리의 연애 풀이"
소속은 §3-1로 해소.

### §3-5 구채팅형 경로 차단
`prompt.ts`의 `STYLE_BY_SLUG["couple-match"]`가 결제 확인(`orders/confirm`)에서는 이미
도달 불가(early return)였으나, **인증 없는 데모 라우트 `/api/saju/interpret`에서는 실제로
살아있었음** — `slug=couple-match`+`partnerBirthInfo`를 직접 호출하면 결제 없이 옛 채팅형
5섹션·두리 톤 "가짜 궁합"이 생성 가능했다. `interpret/route.ts`에 슬러그 진입 시점 하드
차단을 추가(전용 파이프라인 안내 메시지로 400 응답)하고, `STYLE_BY_SLUG`의 couple-match
항목과 `interpret/route.ts`의 관련 분기는 삭제 대신 폐기 주석으로 표기(과거 3중 방어
이력 보존).

### §4 love-consulting
`products.seed.ts`·`couple-fixed-sections.ts` upsell 문구 검토 — "PDF"·"리포트"·"페이지"
등 채팅형 실제 제공물과 어긋나는 과대 표현 없음 확인, **코드 변경 없음**. 30p 재설계
기획 미착수.
