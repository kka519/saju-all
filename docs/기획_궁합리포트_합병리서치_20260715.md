# 기획 확정 — 궁합 리포트 "커플 합병 리서치" (2026-07-15)

couple-match(19,900원)를 채팅형 700~900자에서 **A4 20페이지 PDF 리포트**로 전면 개편.
브랜드는 LUNA LIFE RESEARCH 라인(두리 아님). 클로드 코드는 이 문서를 사양서로 사용.

## 0. 착수 조건·전제

- couple-match 상대방 입력(폼·저장·2회 호출·프롬프트 게이트) 커밋 완료 후 착수 — **그 작업은 폐기가 아니라 재사용**: 입력·저장·2회 fetch·가짜 궁합 차단 게이트는 그대로, 출력단(채팅형 → 리포트 파이프라인)만 교체
- 윤달 입력 작업과 파일이 겹치면 윤달 먼저 (작은 작업 우선)
- 리포트 런타임 모델: **Sonnet 고정** (인수인계 §3 — 원가 전제)

## 1. 확정 결정 (7/15 사장님)

- **분량**: A4 20페이지 PDF. 근거: 19,900원에 2,000자 텍스트는 "성의 없음+비쌈" 체감. 고객이 돈 쓰고 아깝다는 생각이 들면 안 됨
- **브랜드**: LUNA LIFE RESEARCH "합병 리서치" 컨셉 — 두 종목(두 사람)의 합병 실사 보고서. 리포트 엔진·NAVY/GOLD 토큰·백테스트 장치 재활용
- **진열 이동**: couple-match를 홈 ③두리의 연애 풀이 → ②LUNA LIFE RESEARCH 섹션으로. **구매 동선(카드·상세·대기·완료·PDF)에 두리 등장 금지** 원칙이 couple-match에도 적용됨 (7/14 별도 페르소나 원칙 확장)
- **속궁합 포함, 수위 상한 있음**: 전용 1페이지(케미스트리 리포트). 도화·홍염·일지 기반으로 끌림·스킨십 케미·속도 차이를 솔직하고 구체적으로 다루되, **노골적 성행위 묘사는 프롬프트 금지 + 게이트 차단**. 근거: PG 심사(성인 콘텐츠 분류 리스크)·메타 광고 정책. PG 심사 통과 후 수위 재검토 가능
- **love-consulting(29,900)**: 비노출 아님 — 궁합 리포트보다 상위 가치로 재설계(별도 회의, §8)

## 2. 콘텐츠 설계 원칙

고객이 궁합에서 진짜 원하는 것 (우선순위 — 7/15 회의):
① 상대가 나를 어떻게 경험하는가 ② 반복되는 싸움이 구조 때문임을 확인(죄책감 해소) ③ 오래 가는가/결혼까지 가는가 ④ 위기 시기와 예방 ⑤ 상대 사용설명서(화해법) ⑥ 속궁합 ⑦ 돈 궁합

**핵심 서사: "우리가 싸우는 건 사랑이 부족해서가 아니라 구조 때문이고, 다룰 수 있다."**
판정(점수)은 훅, 본체는 '관계 사용설명서'. 킬러 장치는 **커플 백테스트** — 두 사람 대운·세운 교차로 "가까워진 해·흔들린 해"를 먼저 맞히고 신뢰를 얻은 뒤 미래를 말한다.

## 4. 속궁합(p13) 수위 규정

- 허용: 스킨십 케미·애정 표현 방식·끌림의 강도·속도 차이·표현 욕구의 온도차를 성인 대상으로 솔직하게. "업계 통상 궁합보다 한 단계 솔직" 수준
- 금지(게이트): 성행위 직접 묘사, 신체 부위 명시, 외설 표현. 금지어 목록은 term-guard 패턴으로 구현
- 근거: PG 심사 성인 콘텐츠 분류 리스크 + 메타 광고 정책. 수위 상향은 PG 통과 후 사장님 재결정 사항

## 5. 진실 원천 단일화 (게이트 사양)

today-fortune 패턴("코드가 판정, LLM은 준수, 게이트가 검증") 전면 적용:

1. **관계 지수·등급**: 코드가 계산 — 천간합·지지합충 카운트, 오행 보완도, 용신 교차 매트릭스(내 용신이 상대에게 희신인가 기신인가). 산식은 구현 시 설계하되 **LLM 임의 점수 부여 금지**, 게이트가 본문 등급 표기와 코드 판정 일치 검증
2. **용신 게이트**: 본인·상대 용신/희신/기신 오행을 full_analysis에서 코드가 추출(buildMyeongsikView 재사용), "[이 값만 사용]" 블록 주입. 출력 파싱해 불일치 시 재생성(파트당 상한 2회, 리포트 재시도 패턴 재사용). **mock 폴백 시 용신 언급 금지 분기** — 데이터 없으면 지어내기 원천 차단
3. **상대 일간 인용 게이트**: 양쪽 일간이 본문에 실제 등장하는지 검증 (가짜 궁합 2차 방어)
4. **연도 라벨**: 코드 계산·주입, LLM 임의 부여 금지
5. **용어 규칙**: term-guard 커플판 — 신살 원어 본문 금지(표·각주만), 12운성 원어(死 등) 노출 금지, 흉살은 일상어 번역. 투자 용어 주객전도 원칙 동일

## 6. 파이프라인 이식

- 인생 리포트 비동기 구조 복제: 결제 confirm → pending 행 생성 즉시 응답 → 백그라운드 generate → PDF 렌더 → 완료
- 테이블: `life_analyst_reports` 재사용(+product_type 컬럼) 또는 `couple_reports` 신설 — 구현 판단, 단 stage/progress_pct 등 대기 화면 계약은 동일하게
- 파트 분할 생성(리포트 4파트 패턴): 파트 경계는 페이지맵 기준 4~5파트 권장. 불합격 파트만 재생성(캐시 재사용)
- PDF 템플릿: report.hbs 변형 — NAVY/GOLD 유지, 2인 비교 레이아웃(명식 2단, A/B 장) 추가
- 원가 추정: luckyloveme 2회 + Sonnet 4~5파트 ≈ 건당 1,500~2,000원. 19,900원 마진 충분. **luckyloveme 소진 2배 가속 — 본인 키 발급 항목 우선순위 상승 재확인**
- 생성 소요시간 측정 → 결제 전 "약 N분 내 발행" 고지 (인수인계 §2 고객 기대치 설계와 통합)
